# Acceptance Guide: Workstation outbound HTTP(S) proxy

Run these scenarios against each installed Windows and Ubuntu artifact. Use a disposable workstation profile, a synthetic OpenAI-compatible provider, an authenticated forward proxy, and synthetic credentials. Use a dedicated test environment with no real provider traffic.

1. Install the corresponding workstation bundle. Record OS, build identifier and Docker versions. Run `engineering-memory setup` with a legacy profile missing all three proxy keys. Confirm it loads and can complete a synthetic request using an ordinary reachable provider fixture.
2. Place a test origin behind the proxy on an isolated network. Give LiteLLM a route to the proxy only. For example, publish the proxy via a reachable host-gateway address and leave the origin unexposed. Use a provider hostname outside the mandatory and custom bypass list. For HTTPS use a test certificate trusted by the pinned runtime and keep verification enabled.
3. With the proxy cleared and independent Docker proxy defaults absent, attempt the synthetic completion via installed LiteLLM. Require failure and no observation at the origin. Confirm the local stack is still healthy using `engineering-memory stack status` and the local readiness path.
4. In `engineering-memory setup`, set the proxy URL, keep the origin API base and start the stack. Accept the provider-route check. Require the expected synthetic completion plus a matching proxy request or CONNECT record and origin observation. Correlate by a dedicated fixture hostname/port and time window. Repeat for an HTTP origin to exercise the HTTP route and with a TLS-enabled forward proxy to exercise an HTTPS proxy URL. Use the fixture CA for each TLS hop.
5. Repeat with a replacement proxy and confirm only the replacement observes the request after `engineering-memory stack start`. Clear the managed settings in setup, start again, and verify direct routing on the reachable control origin. Against the isolated origin require failure again. Verify loopback, Hindsight and LiteLLM local connectivity with proxying enabled.
6. Check a proxy endpoint that cannot be reached and one that rejects authentication. Require actionable CLI guidance, a healthy local stack and absence of synthetic username, password, URL and authentication-header markers from terminal output, logs and retained evidence. Retain the scenario outcomes, redacted timestamps and platform/build details only.
