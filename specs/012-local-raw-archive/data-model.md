# Data Model: Local Raw Archive

## Identity and addressing

The existing normalized model remains authoritative. `document_id` is the source plus its opaque native ID, generated by `Conversation.document_id`, never reconstructed by splitting a native ID. The storage key is the lowercase SHA-256 hex digest of the complete UTF-8 document ID.

```text
<archive_root>/
└── v1/
    ├── <64-character-digest>.json
    └── .<temporary-name>.tmp  # unpublished, ignored by readers/enumeration
```

No source ID or title is used as a path component. Verify the configured root and version directory are real directories; reject symlinked record paths and redirected version directories rather than reading/writing outside the configured root. The root itself is trusted operator configuration, not source data. No guarantee against a hostile local process replacing directories concurrently is introduced.

## Version-1 envelope

| Field | Meaning / validation |
|---|---|
| `format_version` | Integer literal 1; unsupported versions are rejected. |
| `document_id` | Full stable identity; equal to enriched identity and requested ID, with filename digest checked. |
| `enriched` | Complete existing `EnrichedConversation` JSON representation, restored with existing model validation. |
| `content_hash` | Equal to the reconstructed enriched conversation's content hash. |
| `original.media_type` | Exact nonempty media type from `OriginalPayload`. |
| `original.content_base64` | Strict base64 of exact bytes, including empty or non-UTF-8 payloads. |
| `original.sha256` | SHA-256 of original bytes; checked on load. |

The private persistence model forbids unknown fields so unsupported data is rejected instead of discarded. Use existing enriched serialization, including every optional field, Unicode, timestamps, provenance and typed tags. Do not change normalization hashing or tag conventions. Hashes detect accidental integrity errors, not malicious modification by a local user who controls storage.

No independent index, history table, or import-state fields. The normalized form is sanitized before store by its caller; the archive cannot infer whether a caller ran a sanitizer. Originals intentionally retain original secret values on local storage and must never flow into consumer output or logs.

## State transitions

1. Absent → private temporary envelope → committed record after replacement.
2. Committed A → private temporary B → committed B; readers see complete A or B.
3. Failure before publication → A remains (or absent for a first write); remove ordinary temporary leftovers.
4. Failure after publication, during durability synchronization → complete B may be visible, but report an availability failure. A retry replaces the same identity safely.
5. Crash leftovers remain unpublished and are ignored by enumeration; deletion/garbage collection is not a user-facing operation here.

`store` returns only after the platform's supported durability steps succeed. Closing and reopening must preserve both forms; sudden power-loss guarantees depend on the filesystem/platform and are not generalized beyond tested support.

## Enumeration and replay

Listing reads one committed envelope at a time, validates it, and yields its document ID once. An optional `Source` filter compares the existing normalized source value rather than splitting strings. Ordering is unspecified. Without concurrent writes, repeated enumeration returns the same membership. Concurrent writes do not promise a consistent corpus snapshot.

A bad record produces a declared per-record failure and the iterator advances past that entry so the caller can continue. An unreadable directory produces a terminal availability failure. Temporary files are ignored; malformed names that look like committed JSON records are rejected explicitly rather than silently treated as absent data.

Replay retains the original payload unchanged and reparses it into a fresh `Conversation` before current sanitization/classification/enrichment. Archive-read failures keep their archive boundary category; malformed JSON, unsupported source media type, parsing errors, and reconstructed-identity mismatches become safe `SourceFormatError` values. The iterator remains usable after document-specific failures.
