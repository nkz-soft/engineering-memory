# CLI and MCP contract

- CLI: `engineering-memory deep-recall "Why did we change the cache policy?" --project demo --json`. Without `--json`, render status, entries, anchors and coverage for a person. A valid result exits 0 for `completed`, `partial` or `insufficient_evidence`; validation or provider errors exit nonzero, including `verification_failed` (emit its coverage).
- MCP (stdio): `deep_recall` accepts `{"query":"Why did we change the cache policy?","project":"demo"}`. Validate strict types and reject extras. Use existing safe MCP errors for bad input or operational failures. Verification failure is a structured result with an empty timeline. Valid structured responses have the same shape as CLI JSON.
- Status: `completed` means verified entries with no known truncation or skipped evidence. `partial` means verified entries with explicit gaps. `insufficient_evidence` means no supported entries could be established. `verification_failed` means malformed or unsupported synthesis and suppresses the entire draft. Provider or backend unavailability is an operational error.
- Each timeline entry has `text` and `citations`; each citation has `document_id`, `message_index`, `field`, optional `tool_index`, `timestamp` (nullable), and `quote`. Resolve by requesting `get_conversation` at that message offset. Narrative entries are paraphrases; reject quote markup in model text, raw provider citations, dates exposed as structural fields, and unknown selectors. Render quoted text from the selected passage only. Reject a claimed quote that fails the shared whitespace-normalized substring check against that exact passage.
- Initial caps per request: 3 unique recall queries with a limit of 10 hits each, at most 30 inspected hits total (also cap a misbehaving adapter locally), 6 distinct normalized record loads including failed reads, 2 selected pages per record (25 messages each), 48 KiB of sanitized evidence text total measured as UTF-8, and 1 synthesis call with at most 30 seconds elapsed and 16 KiB of response bytes. Max 12 timeline entries and 4 citations per entry. Include stable coverage reasons where a cap prevents work or a retrieval window may have omitted hits. Never issue an extra call to probe for depletion.
- Exact project scope: apply only the caller's validated project tag on every recall call; reject foreign hits before ID lookup or archive reads. After loading, verify document ID, provenance and exact project tag before extracting text. Synthesis gets the question and only admitted text with request-local selectors. No originals, paths from the archive, recall snippets, or foreign text.
- Access configuration: expose dedicated opt-in synthesis endpoint/model settings and optional key through the existing environment conventions. Document that bounded sanitized project excerpts and the question are sent there. If absent, existing tools start normally and Deep Recall reports `unavailable`. Do not follow redirects or fall back to a default remote service.
