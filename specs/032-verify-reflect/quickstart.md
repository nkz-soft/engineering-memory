# Validation Quickstart

1. Run `uv run --locked pytest -q` for offline verification, including the stdio test against synthetic data. Run the focused pinned-engine contract with the existing live-contract opt-in described in [local deployment](../../docs/development/local-hindsight.md).
2. Configure access to the accumulated local bank and its sanitized archive using the existing [coding agent setup](../../docs/operations/coding-agent-memory.md). Record the engine and model profile, rough corpus size and date range, project-model availability, and recall limit (ten results). Choose a window without concurrent imports or model refreshes.
3. Under ignored local storage, prepare six synthesis cases across evolution and decision questions plus two direct lookup controls. Choose synthesis cases whose expected relationships require multiple conversations. Freeze question text, project scope, expected points and local references before either call.
4. Once implemented, run `uv run engineering-memory evaluate reflect --cases data/reflect/cases.json --output data/reflect/run.json`. Confirm both outcomes for every case, even if one failed. An empty, unavailable, or changing bank means the live comparison is inconclusive.
5. Compare returned evidence and generated claims with the sanitized sources. Mark coverage per expected point. Record whether the answer added a relationship supported by two or more conversations, whether it ordered changes correctly, and whether it made unsupported claims. For lookup controls, check whether the target fact appears in the returned evidence.
6. Publish reviewed aggregate results with scope, configuration, sample size, latency and failure counts. Use recall for direct lookup and reflect when a supported answer requires connecting evidence across conversations and its observed cost is acceptable. For insufficient evidence, use recall and open the relevant sanitized sources.
