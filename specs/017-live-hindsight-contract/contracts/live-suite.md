# Live Suite Contract

This internal verification feature introduces no application API.

- Local execution requires ENGINEERING_MEMORY_LIVE_STORE=1. Existing ENGINEERING_MEMORY_LIVE_STORE_URL and optional ENGINEERING_MEMORY_LIVE_STORE_TOKEN remain supported.
- CI explicitly selects the live suite; zero tests, any skips, missing configuration, unavailable services or assertion failures fail the job.
- Each contract assertion identifies ARCHITECTURE §6, §9 or §10. Helpers include the active scenario's section in errors.
- All engine calls use the pinned real service. Only its OpenAI-compatible extraction dependency may be a deterministic fixture.
- The fixture accepts the pinned extraction protocol, returns controlled synthetic facts, records request counts and rejects unknown schemas/prompts. It supplies no engine retain/recall routes.
- Pending/completed retries reuse one operation id and identical payload. A new replacement uses a new operation id but the same document id.
- Polling, readiness and overall CI execution have finite deadlines. Acceptance is not completion.
- Tag truth tables assert returned identities, with positive controls and no reliance on result position.
- Historical checks assert original-time fields and supported temporal selection, with reverse ingestion order.
- Teardown removes only resources generated by the current test run. Cleanup failures are visible without hiding the original failure.
